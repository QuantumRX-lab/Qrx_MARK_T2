# Chomp Arena — Full-Repo Review, 2026-08-26

Six independent review lenses (playability, game feel, icons, contrast, defects,
MBSE tree), every finding required to cite `file:line` evidence, and every
citation then re-checked against the actual files by a second, sceptical pass —
including checks against `decision_log.yaml` for conflicts with logged
decisions. 57 of 59 findings confirmed; 2 partially refuted (corrections noted
inline). Priorities: **P1** = biggest playability payoff. Effort: S/M/L.

The owner's brief: *more playable, more realistically fun, better item icons,
more satisfying kills and collections, better floor/wall contrast, and a look
at the MBSE tree structure.*

---

## 0. The pattern

One failure class dominates: **features that exist in the source and do not
exist for the player.** Camera shake is implemented and never called. Upgrade
plinths charge money and change nothing. Hold-to-fire exists only on a
keyboard the iPad doesn't have. Wave-clear is written to an attribute nobody
reads. The combo system is two config keys with no code. The game is
completely silent.

Second class: **the code contradicts its own logged decisions** in three
places (§1) — the tree said the right thing and the build drifted.

Third: the tree's records have started lagging the game (§7) — five APPROVED
requirements describe a game that no longer exists.

## 1. Broken promises — code that contradicts a logged decision (fix first)

These are bugs by the project's own definition: the decision log rules one way,
the code does the other.

- **The shield does not protect the carry.** The steal runs unconditionally
  *before* the shield check; the shield only swaps damage for knockback
  (`GhostService.server.lua:427-451`). D-CHOMP-051 decided "an active shield
  absorbs the contact and throws the ghost clear instead." Ghosts are point
  thieves — the steal IS the hit. Three lines reordered. **[P1/S]**
- **Jumping zeroes the whole charge bar.** `ChargeService` gates on
  `JumpCost` (60) then sets charge to 0, eating up to 40 charge silently —
  and the HUD renders `charge/JumpCost`, so the loss is invisible.
  D-CHOMP-064's own decision text says "the jump costs 60 rather than the
  whole 100 bar". Change the zero to a subtract; a full bar then buys a jump
  plus a 40-point head start. (The stale "costs the WHOLE bar" header comment
  in ChargeService is pre-064 text — fix it in the same commit.) **[P2/S]**
- **Upgrades do nothing, and the shop can never sell level 2.**
  `GarageService` writes `ChompUpgrade<track>`; nothing reads it —
  `MovementService.statsFor()` still carries the `TODO(CHAIN-ECONOMY)`.
  Verifier corrections: the offer hardcodes `Upgrades.Costs[1]`, so every
  level costs $150 and $400/$900 are unreachable; and
  `Progression.effectiveStats` is an `error('not implemented')` stub — wiring
  it naively would crash movement for upgraded players. Implement
  effectiveStats (the config effects are already specified at
  `ChompConfig.lua:116-118`), read the attributes in statsFor, and price by
  current level. A child who saves $150 for "Speed I" must get a faster kart.
  **[P1/M]**

## 2. Playability

- **[P1/M] On iPad you cannot fire while steering.** A second touch is
  discarded (`InputController.client.lua:117`); hold-to-fire is gated on the
  Space key; tap-fire spends the *steering* finger. The 9/s machine gun, the
  auto-lock, the whole combat loop is keyboard-only on the target device.
  Fix: a second finger while the stick is held becomes a fire touch — fire()
  per Heartbeat while it lives; the server already paces the rate. Keep
  stick-tap for one-handed play. *Conflicts with D-CHOMP-027's "a second
  touch is ignored" and D-CHOMP-045's tap-to-fire; supported by D-CHOMP-056's
  held-trigger intent — the decisions are already in tension and need a
  ruling (§8).*
- **[P1/S] Ghost speed grows without a cap and crosses the Standard kart at
  wave 9** (HeavyJaw at 8) — and since ghosts fly over walls while karts
  corner, *effective* parity lands around wave 5-6. "You can always drive
  away" silently stops being true. Fix: `Waves.MaxSpeed = 24`, clamp in
  GhostService; escalate late waves by count and payout instead. *Partial
  conflict with D-CHOMP-059 ("grow in count, speed and payout") — but it
  enforces D-CHOMP-049's "slower than a Standard chassis". §8.*
- **[P1/M] Ghosts ignore every maze wall.** No raycast anywhere in
  GhostService; they cut chords through brick at y=8 — exactly wall-top
  height, so they visibly skim half-embedded. The maze constrains only the
  player; route-planning does nothing against the game's only threat. Fix:
  one raycast per ghost per Heartbeat, slide along the hit exactly as the
  sanctuary code already slides. 22 rays/frame is nothing. *D-CHOMP-063's
  "ghosts cross any ring freely" was about removing the fence rule, not
  endorsing wall-clipping — but flag the sentence when amending.*
- **[P1/S] The home sanctuary encloses a ghost-proof pellet farm** —
  ~1,750 carried per sweep across four lanes inside the 150-stud bubble,
  bank pad in the middle, 12s respawn. The optimal strategy is to orbit the
  spawn forever. (Self-inflicted: D-CHOMP-065 added the sanctuary over
  existing pellet lanes.) Fix: PelletService skips pellet positions inside a
  sanctuary, keeping only the 10-value rim trail so the first minute still
  teaches eat-then-bank. **Consistent with D-CHOMP-065's own rationale.**
- **[P1/S] Pellet values flatten where the map gets dangerous.** The 4-entry
  value table is clamped over 7 lanes, so the inner four ALL pay 150 — the
  scariest geography pays the same as the safest rich lane. Fix: 7-entry
  table `{10,20,35,60,90,130,180}` outer→inner; every ring inward is a
  visible raise and the centre is unambiguously the jackpot.
- **[P2/S] A pack brush is a deletion, not pressure.** Steal cooldown is
  per-GHOST, so four ghosts take 68% of the carry and 56 of 100 health in
  one instant. `Ghosts.ContactCooldownSeconds = 1.6` exists in config and is
  read by nothing. Fix: per-player contact window using that key (consider
  2.5); keep the per-ghost cooldown too. Worn down, not deleted —
  which is what D-CHOMP-051 said.
- **[P2/M] Death is five silent frozen seconds.** No `Humanoid.Died`
  handler, default RespawnTime, the world-locked camera parked on a corpse,
  belt and carry gone with no explanation. The single most tears-likely
  moment. Fix: `Players.RespawnTime = Combat.RespawnSeconds` (4.0 — exists,
  unused), gold shard burst on death, HUD "CAUGHT! Back in 3…2…1".
  *Soft conflict: D-CHOMP-051 called death "an ordinary Roblox death" —
  written before waves could swarm-kill.*
- **[P2/S] Wave 1 is nine ghosts for one player and for eight.**
  `ghostCount()` and `Ghosts.CountByPlayers` are dead code — the
  fewer-players scaling never runs. Solo wave 1 = a siege at the sanctuary
  line. Fix: scale wave one by lobby (5 solo / 7 duo / 9 at three-plus).
  *Conflicts with D-CHOMP-062's "nine rather than four" (§8). Note
  CHOMP-SYS-053 mandates the inverse mapping — the requirement needs
  amending either way (§7).*
- **[P2/M] No wave-clear moment, no remaining count, unusable break.**
  `ChompWaveCleared` and `ChompWaveCount` are write-only; the HUD says only
  "WAVE n"; the 6-second break covers ~158 studs of a 2,388-stud rim. The
  tail of every wave is hunting 1-2 invisible-on-HUD stragglers across an
  800-stud disc. Fix: "WAVE 2 — 3 LEFT" from a new `ChompWaveAlive`; a real
  WAVE CLEAR banner + countdown; `BreakSeconds` 6 → 15; when ≤2 remain, drop
  the sense gate so stragglers come to you.
- **[P2/S] HeavyJaw — the first purchase the ladder points at — is a strict
  downgrade.** Slower, clumsier, and its advertised advantages (BarCapacity,
  Power) are consumed by no system yet. A trust-breaking purchase. Fix
  until the bite-combat chain ships: give it a wave-relevant perk (ghosts
  steal half from it) or match Standard's speed and keep the turn trade.
- **[P3/M] Pressure is monotone — no chase/scatter rhythm.** Pac-Man is
  survivable for children because pressure comes in swells. Fix: 20s
  chase / 6s scatter on a shared staggered timer (the scatter behaviour —
  ring drift — already exists as the no-target branch). *Conflicts with
  D-CHOMP-049's "relentless" (§8).*
- **[P3/M] Tuning the game from ChompConfig will silently fail.** Live
  balance literals hide in services (`STEAL_RADIUS`, `SENSE_RADIUS`, bank
  radius, cannon hit radius, both PvP damages) against CHOMP-SYS-037's
  no-literals rule, while ~10 config keys are dead (ContactCooldownSeconds,
  CountByPlayers, Combo*, ReverseFlip* — the last kept deliberately by
  D-CHOMP-033). Fix: move the seven literals into config; mark dead keys
  as unimplemented rather than deleting the decision-protected ones.

## 3. Kills and collections — making it FELT (all 11 findings verified)

- **[P1/M] The game is silent — zero Sound instances in src/.** Half the
  reward loop for a seven-year-old is audio, and every attribute stamp
  needed to drive it already exists (`ChompGainedAt/BankedAt/StolenAt/
  HurtAt/BoughtAt/WaveCleared/JumpedAt`). One `SoundFeedback.client.lua`
  mirroring PickupFeedback's stamp-watcher: pellet blip with pitch rising
  per streak, coin-pour on bank, descending sting on steal, padded thud on
  hurt, register on buy, fanfare on wave clear, whoosh on jump, light pew
  per cannon shot, boom on bomb. Randomise PlaybackSpeed 0.95-1.05.
- **[P1/S] Camera shake is fully built and never fired.** `_G.ChompCameraShake`
  is implemented, tuned, applied in the camera loop — and has zero callers.
  Call it on hurt (1.0), steal (0.5), nearby bomb blast (1.6, distance-scaled).
  The cheapest single feel win in the codebase.
- **[P1/M] A ghost kill pays into the same attribute channel as banking** —
  same gold "+$X SAFE" popup over your own kart, and a kill landing the same
  frame as a bank silently overwrites one of them. Kills get their own
  channel (`ChompKillAmount/At`), a "+$200 GHOST!" popup in Danger red at
  1.3×, and a PointLight flash + two big shards at the death site so the
  kill reads across the corridor.
- **[P2/S] Cannon feedback is inverted: walls spark, ghosts don't.** Add
  `sparkAt(pellet.Position, P.Danger)` in the ghost-hit branch, a muzzle
  flash (the existing 0.12s spark at the muzzle origin), and an optional
  PointLight on sparks so corridors light up as you fire.
- **[P2/S] The bomb appears at full size, sits, vanishes.** Tween 8→92 studs
  over 0.3s, ground shockwave ring, PointLight, `ChompBlastAt` for shake.
- **[P2/M] Banking has no ceremony and the chest ignores you.** Lid-pop +
  gold-swell + light on deposit, coin burst at the kart, bigger popup past
  $250. The tensest drive in the game needs a landing.
- **[P2/M] Pellet eating never escalates.** `ComboWindowSeconds`/`ComboMax`
  exist, wired to nothing; every popup identical; pellets blink off. Streak
  popups ("+10 ×3", growing, colour-stepping), a birth-pop tween, mouth
  burst, and the pitch-rising eat blip. *Note: CHOMP-SYS-006 specifies the
  combo as a value multiplier that resets on wall hits — the client-side
  presentation streak is a stepping stone, flag the difference when wiring.*
- **[P2/M] Purchases confirm nothing** (`ChompBoughtWhat/At` write-only, 1.2s
  dwell with no progress, silent refusal). Dwell progress bar, "CANNON −$120"
  popup, "NEED $120"/"BELT FULL" refusals — the charge button's refusal
  pulse already set the precedent.
- **[P2/S] A shield save looks identical to shield failure**, and the ghost
  teleports 40 studs instead of flying. Break-burst (blades flash solid then
  shatter outward), "SHIELD SAVED YOU", knockback velocity instead of
  PivotTo.
- **[P3/S] The jump has no takeoff.** FOV kick 75→83→75 (as an offset — the
  camera re-asserts FOV every frame), launch ring, whoosh, tween the bar
  empty instead of snapping.

## 4. Icons and item readability

- **[P1/M] Belt slots ask a pre-reader to read.** Words in 64×68 boxes.
  Fix: server parents one `ItemModels.build()` of each item into a
  `ReplicatedStorage.ItemIcons` folder; each slot gets a ViewportFrame
  rendering the model from a front-left three-quarter camera, rebuilt ONLY
  when the slot's item id changes (never per-frame — iPad). Word shrinks to
  a caption. Cheap intermediate that ships today: emoji per slot (🚀💣🛡💥)
  with the word beneath.
- **[P1/S] The cannon barrel and jetpack thrusters are flat pucks — a
  Roblox cylinder's length is Size.X.** The barrel is a 1.8-stud blade with
  its caps facing sideways; thrusters are drums. Fix (exact sizes/rotations
  verified): Barrel `(5.6,1.8,1.8)` with `Angles(0, rad(90), 0)`; Muzzle
  `(0.8,2.2,2.2)` same; Thrusters `(2.6,1.1,1.1)` keeping the Z-rotation.
- **[P1/S] The bomb's fins sit flush against the ball** (outer face 1.675 vs
  sphere 1.6 — plates, not blades; verifier softened "swallowed" but the
  silhouette is still ball-with-plates). Fix: fin Size `(2.2,1.8,0.35)` at
  radius 2.3 — a naval-mine spike ring; push the eye to −1.9 so a full
  hemisphere shows.
- **[P1/S, partially refuted] Glow colours cross-wired at distance.** True
  for two of four: the CANNON's only emissive part is its RED muzzle (the
  damage colour) and the BOMB glows TEAL (the jetpack's colour). The
  jetpack half of the original claim was wrong — it already glows its own
  teal. Fix: make each item's dominant emissive part its identity colour
  (gold neon barrel sleeve; NeonB bomb eye + equator band).
- **[P2/M] Pads vanish behind 7-stud walls and read as four same-sized
  hover-blobs.** Static floor ring per pad in the item colour (11 studs —
  teaches the 10-stud pickup radius), shadowless PointLight, build pad
  models at 1.35×. Ring must NOT bob with the model.
- **[P2/M] Roof mounts mash the model** — the scale loop multiplies part
  sizes but not offsets. Use `Model:ScaleTo()` (scales both), raise the
  cannon's mounted scale to 1.35, raise RearMount y 2.4 → 4.6 so the
  carried bomb clears the shell from every camera yaw, add a PointLight in
  the item colour.
- **[P3/S] The last cannon shot shows no count** — `x1` is hidden by the
  `charges > 1` condition, so the slot vanishes mid-burst unwarned. Key the
  display off the definition (`def.charges > 1`), tint red at ≤2.
- **[P2/M, partially refuted] Pad animation** — see §6.

## 5. Contrast, palette, lighting (all 8 verified)

- **[P1/M] Nothing configures Lighting — the dark-neon palette runs under a
  bright 2pm default sky.** Neon barely glows in daylight; walls stripe the
  floor with hard sun shadows; nothing pins the look between Studio
  sessions (the built .rbxlx contains no Lighting either — the Baseplate
  template supplies it). Fix: a managed `Lighting` node in
  `default.project.json` — ClockTime 0, Brightness 1.5, raised violet
  Ambient/OutdoorAmbient, Atmosphere (density 0.28, dark decay), Bloom
  threshold 1.05 so ONLY neon blooms. ShadowMap, not Future (iPad).
  **This one change is most of the requested floor/wall contrast.**
- **[P1/S] Wall tops are invisible from the 38° chase camera** — the maze is
  read off tops, and dark masonry tops sit at 1.2-1.5:1 against the floor.
  Fix: 0.5-stud neon capstone strips on masonry walls (NeonA/NeonB
  alternating), ~250-300 parts. *Tension with D-CHOMP-063's
  neon-as-minority — the caps are trim, not lit walls, but log it (§8).*
- **[P1/S] The centre arena is indistinguishable from the rest of the
  floor** — FloorCentre is 8 RGB points off the floor at 55% transparency.
  Fix: violet glass `(108,52,140)` at 0.35, plus a gold neon kerb at the
  arena threshold — gold already means money.
- **[P1/S] Ring 7 is Concrete-on-Concrete at ~1.2:1 — a wall that reads as
  open space.** Fix: DiamondPlate in a new `Palette.Iron (98,92,118)`; lift
  Slate to `(66,66,88)`. *Amends D-CHOMP-063's named cycle — log it.*
- **[P2/M] The floor is one uniform 800-stud disc.** Per-lane neon bands at
  78% transparency: lane guidance, ring identity underfoot, and streaming
  speed reference. *Tension with "the floor stays out of the way" (§8).*
- **[P2/S] Danger red vs NeonB pink differ only in blue — near-identical
  for the ~8% of boys with CVD.** Shift NeonB to `(208,74,255)`; give
  Danger a motion signal (pulse the guardian walls); make the sanctuary
  line dash-patterned as well as green.
- **[P2/S] Pellets wear the wall colour.** Teal pellets camouflage against
  the teal ring; semantically a pellet IS money. New `Palette.Pellet`
  pale gold `(255,216,138)`; power pellets stay full gold. One colour
  family tells the whole economy story.
- **[P3/S] ~814 wall segments cast shadows** for zero return once the sun
  is down. `CastShadow = false` on neon always, walls under the midnight
  rig.

## 6. Performance on the target iPad

- **[P2/M] ~640 anchored parts are re-CFramed server-side every Heartbeat**
  and replicated continuously: ghost puppets (10 parts each, and **dead
  ghosts are NOT skipped** — the Dead check sits after all movement),
  ~417 pad parts (verifier: exact count), bobbing chests. Fix: (a) move the
  Dead check above movement — one line; (b) animate pads client-side

- **[P3/M] Karts are collisionless against each other** — 8-stud kart,
  2-stud humanoid hitbox; ramming your brother is a pass-through.
  *Deliberately deferred by D-CHOMP-031 pending CHOMP-TC-040, which has
  still never run. Leave until TC-040; then a CollisionShell in its own
  collision group.*
- **[P3/S] Housekeeping:** `SetInputDirection` fires ~20/s with no listener;
  `Debug.CameraReadout = true` keeps debug figures on the child's screen
  (D-CHOMP-029 wants it on until TC-040 — run TC-040, then turn it off);
  ArenaMap/TestMap gate cleanly and can stay.

## 7. The MBSE tree (all 11 verified)

- **[P1/M] Requirement drift — six APPROVED/DRAFT requirements contradict
  the built game:** SYS-047 (multi-deck maps) vs the single-level disc;
  SYS-055 (top corners HUD — DRAFT) vs bottom-right; SYS-007 (banking
  "refused at any other player's garage") vs shared pads; SYS-046 (12
  garages) vs 4; SYS-017/-018/-053 (grid pathing, no-damage ghosts, inverse
  count scaling) vs waves/damage/fixed-9. One triage session, by ID:
  re-phase multi-deck to v2 with its dependents, amend the rest to describe
  the decided game, each citing its decision.
- **[P1/L] 35 test cases claim AUTOMATED; zero automated tests exist.**
  All 47 TCs are NOT_STARTED; Impact.lua and Progression.lua are error
  stubs nothing requires; validate.py passes CRITICAL requirements on the
  automation *string*. Add `automated_by:` (a real runner path) to the TC
  schema, validate it for CRITICAL, then build the three cheapest runners:
  ChompLogic unit specs (the specs are already written as doc comments),
  guard.py map-invariant checks against the built XML, and the TC-042
  exploit-suite skeleton (its attack list is already enumerated).
- **[P1/S] No supersession convention, and D-CHOMP-057 is silently
  missing.** Eight supersessions live only in prose ("the electrified half
  of D-CHOMP-059"); the only way to know the live ruling is to read all
  1730 lines. Add `supersedes:/superseded_by:/status:` fields, back-fill
  the 8 known pairs, tombstone 057, and have validate.py enforce
  reciprocity and ID continuity.
- **[P1/M] The decision log doesn't scale.** 64 entries, one file, design
  decisions interleaved with bug post-mortems. Add `topic:` and
  `kind: DECISION|CORRECTION`, and generate `06_decisions/INDEX.md` from
  validate.py (the same generated-not-handwritten rule verified_by already
  follows). An agent then reads ~5 ACTIVE entries for its topic, not 1730
  lines.
- **[P2/M] A night of mechanics has no requirement IDs** — waves, charge
  jump, sanctuaries, friendly fire, the shop. Chain logs mis-cite nearest
  in-chain IDs (validate.py forces chain membership, so wrong-but-in-chain
  passes). Add SYS-062…066 (waves; charge+jump; sanctuaries; FF gates
  damage; the shop's grant-then-charge) with TCs, noting SYS-041's partial
  FF overlap.
- **[P2/M] Stale test procedures would fail the correct game:** TC-047
  still tests one slot/3-shot cannon/homing bomb; TC-020 demands
  junction-only ghost turns; TC-037/-039 test decks and bridges. Amend in
  the same pass as the requirements; add a staleness warning (TC older
  than the requirement it verifies).
- **[P2/S] The dashboard narrative is two generations stale** ("drive both
  decks, under the bridge"; frontier = camera-and-driving). validate.py
  gains: as_of must be ≥ newest record date; next_actions carry refs.
- **[P2/S] YAML anchors have already silently rewritten "append-only"
  history** in exactly two chains (CHAIN-COMBAT, CHAIN-UI): the ESTABLISHED
  entries alias the header list, so appending SYS-058-061 to the header
  retroactively edited history. Freeze literal lists per entry; four-line
  identity check in validate.py; NOTE entries restoring the original lists
  from git.
- **[P2/S] The risk register keeps abandoned risks and misses found ones.**
  Close RISK-013 (multi-deck cost) against D-CHOMP-046; re-scope RISK-012
  (occlusion; TC-040 still never run — worst Studio reading 0.92s vs the
  0.20s ceiling) and RISK-008 (→ ghosts ignore geometry: farmable through
  walls); add RISK-014 (wave spawn pressure vs a child).
- **[P2/S] control_scheme.md documents the superseded grid scheme** —
  D-CHOMP-042 never re-amended it — and README/HANDOVER carry three
  different wrong count sets ("11 decisions" vs 64). Rewrite the doc to
  D-CHOMP-042 with a "Current as of D-CHOMP-NNN" footer; strip live counts
  from prose — they live in the validated dashboard.
- **[P3/M] Next guard/validate checks, each automating a failure already
  paid for:** deep `allocated_to` path resolution; DRAFT-cited-by-DELIVERED
